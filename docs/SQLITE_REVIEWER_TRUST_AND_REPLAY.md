# v1.0.0-rc.8 — Synthetic reviewer lifecycle and durable replay regression

**Engineering only. Production status stays NO-GO.**

This version extends the internal **synthetic-only** SQLite 1.x → 2.x migration rehearsal. It does not authorize an institution, permit real-data migrations, connect to real owner accounts, or enable the public database upgrade API.

## Concrete implementation

1. **Pinned reviewer key registry:** \`SyntheticReviewerTrustPolicy\` requires exactly two independently identified role entries: \`privacy-security-test-reviewer\` and \`operations-test-reviewer\`. Every key uses ECDSA P-256 SPKI bytes and a SHA-256 key ID matching those exact bytes. The registry requires distinct roles and distinct key IDs, checks the encoded public key, takes defensive copies and allows explicit validity intervals and revocation flags. A valid ECDSA signature is rejected if the reviewer key has expired, is future-dated, has been replaced without being pinned or was revoked.
2. **Key-identity binding:** Each signature now includes the reviewer's key ID as a domain-separated component of the signed message, in addition to the previously signed fixture SHA-256, schema, purpose, random nonce and validity interval. Swapping a key ID or role invalidates the review. All public keys are generated by **two independent disposable in-memory test signers** and pinned by the synthetic test harness. There are NO enrolled real reviewer identities, HSM keys, managed certificates or actual institution trust anchors.
3. **SQLite-persistent nonce tracking:** \`SyntheticDurableReviewNonceLedger\` uses an independent synthetic \`synthetic-review-nonces.db\` file in the same generated temporary fixture folder. A primary-key uniqueness constraint and \`INSERT OR IGNORE\` atomically reject a second use of the same signed approval across independent SQLite connections and ledger instances. The ledger stores only SHA-256 hashes of replay keys and timestamps, never the original fixture hash, signed nonce, SQL record values or private signer material.
4. **Migration uses the durable ledger:** The internal \`SyntheticMigrationRehearsal.Run\` now requires the durable ledger type, not an in-memory-only tracker. A verified pair of signatures is consumed **before** creating any clone, backup, or migration. A second attempted rehearsal using a *newly opened ledger instance* must fail; no second clone is allowed.
5. **Fail-closed negative controls:** CI tests missing/duplicated signers, a forged signature, modified role or key ID, wrong source or schema, invalid nonce/purpose/validity, revoked/expired/future-dated reviewer keys, unpinned key replacement, and replay after reopening the SQLite ledger. It also checks that a *distinct* valid review succeeds after reopening. The original 1.x files remain untouched; previous rollback and schema/integrity/backup validations are retained.

The optional GitHub Actions evidence artifact contains only aggregate synthetic result flags such as \`syntheticDualReviewVerified=true\` and \`durableReviewLedgerUsed=true\`, schema versions and test counts. It includes **no** ledger database, SQLite source file, student names, student IDs, public/private reviewer keys, signatures, file paths, or source-record hashes. The 7-day artifact is **unsigned NO-GO engineering evidence**, not proof of real approval. All SQLite test databases and their WAL sidecars are removed with the generated runner fixture folder.

## Explicit limitations

- The trust registry is built by the local test harness; it is **not** backed by real institutional identity proof, role assignment, certificate issuance, a protected trust store, independent approval workflow, administrator revocation, or an externally signed key manifest.
- A local SQLite file offers **persistence across ordinary restarts**, not tamper resistance or institution-wide availability. Deleting/restoring the nonce ledger or copying an approval to another host can defeat its replay record. It is therefore not a production anti-replay service, even though SQLite uniqueness prevents duplicate inserts on one live file.
- The temporary directory and environment flag are convenience test boundaries, not authentication or privacy authorization. A privileged local attacker can manipulate them.
- The source-data upgrade API remains **unconditionally disabled to external callers**. No code in this release can authorize an actual student-data migration.
- Historical Git privacy handling, licensed/attested Realand vendor DLLs, physical hardware, real guardian consent and enterprise OIDC/row-level scopes, approved encrypted scratch/offsite backups, real pilot and signed multi-owner release GO remain open.
